Security and Sensitive Reporting

Do not use public issues for sensitive reports

Never publish:

* A child’s personal information
* Suspected abuse details
* Credentials or access tokens
* Exploit steps
* Private system logs or internal URLs
* Confidential partner or product information

Current reporting status

A dedicated private security-reporting channel has not yet been published in this repository.

Until one is formally listed:

* Do not test systems without written authorization.
* Do not post sensitive details.
* For an immediate threat, contact the appropriate local emergency service or authority.
* For a non-emergency project concern, open a public issue only if it can be described safely without personal, confidential, or exploitable information.

Responsible disclosure

Once a private reporting channel is established, security reports should include:

* A plain description of the concern
* The affected public component
* Reproduction information with secrets and personal data removed
* Potential safety impact
* Recommended mitigation, if known

Public disclosure should wait until the concern is reviewed and a safe disclosure plan is agreed upon.
